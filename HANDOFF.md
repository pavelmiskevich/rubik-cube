## Как устроена работа сейчас

- **Выкладка** — публикацией релиза GitHub (`gh release create vX.Y.Z --target main --generate-notes`), не на пуш в `main` (#106), и **ждёт подтверждения владельца** — не одобрять за него без его прямой просьбы. Повтор и откат — `gh workflow run Deploy --ref main -f tag=vX.Y.Z`. Подробности — [`deploy/README.md`](deploy/README.md).
- **Обязательные проверки PR — `audit`, `build`, `e2e`**; защита строгая: после вливания соседний PR становится `BEHIND` → `gh pr update-branch N` → дождаться проверок → влить.
- **Сервер общий** — правила и адреса в памяти агента (`project-prod-vps`) и в [`deploy/README.md`](deploy/README.md). Любое действие на сервере: сначала разведка на чтение и снимок соседей (время старта и число перезапусков контейнеров, PID Caddy, коды ответа их сайтов), изменения только в своих путях, проверка до применения, сравнение со снимком после.
- **Параллельные агенты** — только по просьбе владельца. Им не трогать `STATE.md`, `HANDOFF.md`, `TECHDEBT.md`: заметки — в раздел «Для STATE/TECHDEBT» описания PR, документы обновляет координатор одним PR.

## Что сработало

- **Мутационная проверка тестов.** После написания теста — намеренно сломать код и убедиться, что тест падает. Так закреплены защитные свойства входа, скрамбл на момент сохранения, общие счётчики лимита.
- **Сквозной тест на живом сервере находит то, чего не видно в юнит-тестах.** Две копии модуля `rate-limit.ts` в разных слоях сборки Next нашёл только сценарий «прямой запрос → форма»; отладочный вывод в `authorize` подтвердил причину за один прогон.
- **Проверка на проде безвредным запросом** (несуществующая почта) до и после исправления — прямое доказательство, а не вывод из кода.
- **Скриншоты для README на локальной production-сборке с временной базой** и засеянной историей — правдоподобные данные без касания прода и демо-стенда.

## Что не сработало

Не повторять:

- **Долгие агенты без частых коммитов.** Лимит сессии обрывал агентов по два-три раза за задачу; спасало только то, что в задании было «коммить и пушь рано и часто». Давать это в каждом задании.
- **Доверять повреждённому рабочему дереву.** После обрыва два дерева остались без собственного `.git` — git в них резолвился в основной репозиторий. Возобновление агента такое дерево отвергает; помогает удалить каталог и запустить агента заново. Проверка в начале задания: `git rev-parse --show-toplevel` указывает на своё дерево.
- **Судить о сквозных сценариях по `next dev`.** Выход из аккаунта на dev нестабилен, а на production-сборке — нет; job `e2e` идёт на standalone. Спорный результат перепроверять так же, как в CI: прогон на `.next/standalone/server.js` (скрипт `test:e2e:ci`).
- **Верить `grep -c $'\r'` в Git Bash** — он врёт; концы строк проверять Python'ом. Файлы для Linux-сервера в `deploy/` закреплены LF через `.gitattributes`.
- Всё из прошлых HANDOFF в силе: перед работой `gh issue view N --comments`; тексты с апострофами — через `Write` и `--body-file`; `gh issue create` пачкой параллельно перемешивает номера; `docker compose up -d` без `--build` поднимает старый образ; не резать вывод `gh pr merge`, не использовать `--admin`, не делать `git add -A`.

## Окружение

- **Docker Desktop должен быть запущен** — без него git-хуки (gitleaks) не пропустят ни коммит, ни пуш. В рабочих деревьях gitleaks молча не работает — гонять из основного репозитория: `MSYS_NO_PATHCONV=1 docker run --rm -v "C:/Projects/Antigravity/rubik-cube:/repo" zricethezav/gitleaks:v8.30.1 git /repo --redact --log-opts="--all"`.
- Демо-стенд: `docker compose --env-file .env.demo.local up -d --build` → http://localhost:3030. Сейчас погашен, тома целы. Личный `.env` владельца устарел, но **перезаписывать его нельзя**.
- Временная база для сквозных сценариев с базой: `docker run --rm -d --name rubik-e2e-pg -e POSTGRES_USER=e2e -e POSTGRES_PASSWORD=e2e -e POSTGRES_DB=e2e -p 127.0.0.1:5496:5432 postgres:16-alpine`, затем `npx prisma migrate deploy` с `DATABASE_URL`, в конце `docker stop`.
- Рабочих деревьев агентов, временных контейнеров и dev-серверов не осталось. В локальном репозитории висят старые влитые ветки (`docs/*`, `feature/issue-5-*`, `feature/issue-6-*`, `feature/issue-38-*`, `master`) — не мешают.
