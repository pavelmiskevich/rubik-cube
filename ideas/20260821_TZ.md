# Техническое задание: Проект "Сайт обучения собирать кубик-рубик"

## 1. Описание проекта
Интерактивная образовательная платформа для обучения скоростной сборке кубика Рубика (спидкубинг). Платформа сочетает в себе 3D-тренажеры, официальный генератор скрамблов WCA, умный таймер и систему отслеживания прогресса (статистика Ao5, Ao12). 

Проект разрабатывается с использованием AI-агента agy (antigravity). Вся разработка и багтрекинг ведутся через публичный репозиторий GitHub (через GitHub Issues).

## 2. Стек технологий
* Frontend: Next.js (App Router), React, TypeScript.
* Стилизация: Tailwind CSS (Mobile-First подход).
* 3D-графика: @react-three/fiber (интерактивный куб на WebGL).
* Backend: Next.js Server Actions / API Routes.
* База данных: PostgreSQL, ORM Prisma.
* Авторизация: NextAuth.js (Auth.js) — Google OAuth + Локальная авторизация (Credentials).
* Инфраструктура: Docker, Docker Compose, Caddy (веб-сервер), GitHub Actions.

## 4. Инфраструктура и Docker (Абсолютная изоляция)
Так как проект будет развернут на сервере с уже существующими сервисами, он не должен влиять на соседние проекты и конфликтовать по портам (особенно 80, 443 и 3000).

1. Сеть контейнеров: Создается изолированная сеть rubik-network.
2. Отсутствие проброса портов для БД и Приложения: Сервисы app (Next.js) и db (Postgres) НЕ ИМЕЮТ секции ports в docker-compose.yml. Они доступны только друг другу внутри своей сети.
3. Caddy как локальный прокси: Внутри сети работает контейнер caddy, который слушает внутренний порт 80 и проксирует запросы на app:3000.
4. Динамический порт хоста: Наружу пробрасывается только порт Caddy через переменную окружения в .env (например, ports: - "${HOST_PORT}:80"). Это позволяет главному веб-серверу хоста (Nginx/Traefik) маршрутизировать трафик на этот специфический порт.

## 5. Безопасность и Защита от утечек (CI/CD)
Поскольку код хранится в публичном репозитории GitHub, безопасность секретов — наивысший приоритет.

* Хранение секретов: Все .env файлы надежно скрыты в .gitignore. В репозитории хранится только .env.example без реальных данных.
* Локальные проверки (Husky & Gitleaks): Установлен Git-хук pre-push через husky. Перед каждой отправкой кода в репозиторий утилита gitleaks проверяет коммиты на наличие ключей, паролей и токенов. При обнаружении утечки пуш жестко блокируется.
* Авторизация: Хеширование паролей (bcryptjs), JWT-токены в HttpOnly cookie, защита от XSS и SQL/NoSQL-инъекций (благодаря Prisma).
* Права доступа в Docker: Контейнер Next.js запускается от лица пользователя nextjs (Non-root user).

## 6. Стратегия тестирования (QA)
* Unit-тестирование (Jest): 100% покрытие бизнес-логики генератора скрамблов WCA и калькулятора статистики (Ao5, Ao12).
* E2E-тестирование (Cypress): Имитация полного цикла пользователя от регистрации до сохранения результатов сборки кубика.
* Оптимизация: Строгий контроль производительности 3D-анимаций (Three.js) на бюджетных мобильных устройствах.

## 7. Рабочий процесс для AI-агента (agy)
Все задачи агенту ставятся в виде атомарных ишью (Issues) в GitHub.
1. Агент берет задачу, создает ветку.
2. Пишет код, проходя локальные тесты и хуки безопасности.
3. Создает Pull Request / делает пуш.
4. GitHub Actions выполняет сборку и деплой на сервере (подключение по SSH, git pull, docker compose up -d --build).
