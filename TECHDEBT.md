# Технический долг и принятые решения

## Принятые решения
- **Миграция ESLint:** Мы используем плоский конфиг (`eslint.config.mjs`) с пакетами `eslint@9` и `eslint-config-next@16`.
- **NPM Audit:** Запуск `npm audit` в пайплайне вынесен в отдельный job с `continue-on-error: true`.
- **Caddy Proxy:** Caddy используется для проксирования Next.js на локальный порт (и HTTPS-шлюз). Контейнер настроен отдавать 4 security-заголовка.

## Отложенный технический долг (до релиза в Production)
Следующие задачи помечены как не блокирующие разработку и будут решены позже, перед боевым развертыванием проекта:
1. **Content-Security-Policy (CSP):** Настроить и включить строгий CSP (на данный момент отложено из-за конфликтов с hot-reload в Next.js App Router).
2. **Сборка миграций (migrate service):** Сейчас сервис применения миграций собирается из стадии `builder` вместе со всеми devDeps и исходниками. Нужно выделить отдельную легкую стадию сборки для `migrate`.
3. **Инварианты БД (timeMs / isDNF):** На уровне Prisma/SQL необходимо добавить CHECK constrain на `timeMs >= 0`, а также ограничение взаимоисключения для `isDNF` и `isPlusTwo` (они не могут быть `true` одновременно).
4. **Уязвимости в транзитивных зависимостях Prisma CLI:** В `npm audit` остаются два high-адвизори, оба приходят через dev-зависимость `prisma`: stack exhaustion в `deepmerge-ts <8` (`@prisma/config`, GHSA-ggr8-5vv4-36mx) и auth-plugin downgrade в `mysql2` (GHSA-3f6p-5ww8-9rcr). Драйвер `mysql2` в рантайм не попадает — datasource провайдер `postgresql` через `@prisma/adapter-pg`. Оба внесены в allowlist `audit-ci` в `ci.yml`; снять, когда Prisma обновит зависимости (единственная альтернатива сейчас — откат на Prisma 6).
5. **Безопасность Credentials-авторизации:** При реализации кастомного провайдера авторизации (вместо OAuth), обязательно использовать `argon2id` или `bcrypt cost >= 12`, применять rate-limiting и настроить константное время ответа сервера для логина. Пароли (`password`) не должны попадать в `select` Prisma по умолчанию.
