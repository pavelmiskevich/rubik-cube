## Что сработало

- **Четыре задачи параллельно, каждая в своём рабочем дереве.** Агенты не трогали `STATE.md`, `HANDOFF.md` и `TECHDEBT.md`, а складывали заметки в раздел «Для STATE/TECHDEBT» описания PR; документы обновлены одним PR после всех вливаний. Конфликтов по документации не было вовсе.
- **Вливание по очереди с оповещением остальных.** После каждого вливания оставшимся агентам сообщалось, что `main` ушёл вперёд и с какими файлами пересечение. Единственный реальный конфликт — импорты в `SolveWorkspace.tsx` между #54 и #55 — агент #54 разрешил сам и проверил в браузере, что работают обе функции.
- **Агента, оборванного лимитом API, можно продолжить** сообщением: незакоммиченная работа остаётся в его дереве, и он продолжает с места обрыва.
- **Подмена камеры потоком с холста** — сквозная проверка распознавания без настоящего кубика (#55).

## Что не сработало

Не повторять:

- **Запускать четыре крупные задачи, не проверив запас лимита.** Две из четырёх оборвались посреди работы на лимите сессии и простояли до сброса.
- **Общий каталог-блокнот без префиксов.** Два агента писали лог в одноимённый файл и затирали друг друга. В задании агенту сразу давать номер задачи для имён файлов и свой порт dev-сервера.
- **Забывать про Docker.** Он был выключен, и без него хуки не пропустили бы ни одного коммита — поднят в начале сессии.
- Всё из прошлых HANDOFF в силе: перед работой читать `gh issue view N --comments`; heredoc с апострофом рвётся (тексты — через `Write`, тела ишью и PR — через `--body-file`); `gh issue create` пачкой параллельно перемешивает номера; `docker compose up -d` без `--build` поднимает устаревший образ; не резать вывод `gh pr merge`, не использовать `--admin`, не делать `git add -A`; проверка «Попробовать» в браузере — через пропсы `LessonCube` в React-файбере: `onRotateEnd()`, затем `onMove({ face, turn })`.

## Окружение

- Демо-стенд: `docker compose --env-file .env.demo.local up -d --build` → http://localhost:3030. Сейчас погашен, тома целы.
- `.env.demo.local` — локальный файл демо-стенда, он в `.gitignore`. Личный `.env` владельца устарел (имена NextAuth v4), но **перезаписывать его нельзя** — там его рабочие значения.
- Рабочие деревья агентов создаются в `.claude/worktrees/` (теперь в `.gitignore`). Все четыре дерева эпика #51 и их локальные ветки удалены после вливания. Удаление идёт минуты: в каждом дереве свой `node_modules`.
